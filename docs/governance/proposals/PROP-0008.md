# PROP-0008: 讓外部的人自己找到、信任並真正使用綠媒

- **級別**: `L3`（對外：公開網址、公開頁面；安全：對外開放寫入）。公開網址與任何以使用者名義的對外動作屬 `L4`，需使用者本人。
- **提案發起人**: `Fable`（依使用者 2026-11-14 指示：在使用者引入外界真實資料之前提高信任度，並讓外部使用者在不是由使用者主動引進的情況下真正使用平台）
- **建立時間**: `2026-11-14 19:0x`
- **狀態**: `HOLD`。A 段已於 19:09 併入 PROP-0007 4d。B、C 段需要公開網址：使用者目前沒有網域，對外與建立信任由使用者的夥伴負責，等他們決定後再開。
- **影響範圍**: 新頁面（關於、方法與出處、資料與隱私）、體檢報告分享、`scripts/serve-prod.mjs`（共用資料 API）、靜態公開頁產生腳本、公開部署

## 0. 現況：為什麼外部的人現在用不了

1. **沒有公開網址。** quick tunnel 11/14 04:31 失效，外部的人根本打不開。
2. **資料只存在每個訪客自己的瀏覽器。** 本機執行時 store 用 `localStorage`（`src/core/store/local.ts`），所以兩邊互相看不到：工廠送出的需求廠商看不到，廠商更正的資料別人也看不到。這是展示品，不是能讓兩方真正互動的平台。
3. **搜尋引擎找不到。** 單一 HTML 加 hash 路由，Google 只看得到一頁。外部的人「自己找到」幾乎不可能。
4. **沒有理由相信。** 全站是虛構示範資料，沒有「我們是誰、數字怎麼算、資料存在哪」。PROP-0006／0007 處理了數字出處，這裡補其餘部分。

## 1. 要 CEO 做什麼

### A. 信任層（不需要公開網址，PROP-0007 之後就做）

- [ ] **關於我們**：國立成功大學團隊、2026 全國 AI 專題創意競賽參賽作品。
  - 寫清楚平台做什麼、不做什麼：不收費、不收廠商費用、不做付費排名、不代為聯絡。
  - 寫清楚推薦怎麼排序，以及利益衝突聲明。
  - 成員真名要使用者同意才放；沒同意前只寫團隊名。
- [ ] **方法與出處**：一頁列出體檢與回本的公式、每個基準值與電價的來源、PROP-0006 的回測表與誤差。
  - 誤差寫成一句老闆看得懂的話，例如「在 N 筆公開案例上，回本年數平均差 X 年」。
- [ ] **資料與隱私**：一句話講清楚資料存在哪裡、誰看得到、怎麼刪。B 段上線前寫「只存在你的瀏覽器」。
- [ ] **體檢報告可帶走**：可列印或存成 PDF（瀏覽器列印樣式即可），頁尾附出處與產生日期。老闆會轉給老闆，這是最自然的口碑。
- [ ] **廠商端入口**：每份公開履歷上有「這是你的公司嗎？更正或補充資料」。B 段上線前先說明「上線後開放」，不放假表單。
- [ ] **全站不得出現假的社會證明**：不寫「已有 N 家工廠使用」、虛構評價、虛構合作標誌。示範資料一律有 `DemoBadge`，且不放在首頁第一屏。

### B. 共用資料（公開網址決定後）

- [ ] 在 `serve-prod.mjs` 加最小的共用資料 API（不加套件），只收三種紀錄：
  - 工廠自願送出的體檢需求（廠商可見）；
  - 廠商的履歷更正或認領申請；
  - 回饋。
- [ ] **安全**：
  - 只收 JSON，限制大小，依 IP 限流。
  - 欄位白名單，不收檔案。
  - 紀錄只增不改；更正申請先進審核佇列，由團隊確認後才顯示。
  - 所有外部文字一律視為不可信資料，不當作指令。
- [ ] 前端送出前清楚告知哪些內容會被誰看到，並要使用者勾選同意。

### C. 讓人自己找到（需要公開網址）

- [ ] 在 build 時產生可被搜尋引擎收錄的靜態頁，連回 app 的體檢入口，並產生 `sitemap.xml` 與 `robots.txt`：
  - 每筆公開案例一頁；
  - 每家廠商公開履歷一頁；
  - 方法與出處一頁。
- [ ] 廠商搜尋自己公司名時會找到自己的公開履歷，再透過「更正或補充資料」進來。這是不靠使用者引介、讓廠商自己上門的主要管道。
- [ ] 工廠端靠「空壓機 節能 補助 試算」這類搜尋找到體檢頁。
- [ ] 量測：伺服器端記錄非團隊、非自動化來源的體檢次數與認領次數（沿用 `browserFamily` 排除規則），每週寫進 `STATUS.md`。不寫進任何對外頁面。

### 驗收

- [ ] A 段：觀察者以第一次來的工廠老闆與廠商兩種身分各走一次，能說出「這是誰做的、數字怎麼來、資料去哪」。
- [ ] B 段：兩個不同瀏覽器之間，工廠送出的體檢需求廠商看得到；限流與大小限制有測試。
- [ ] C 段：公開網址上線後，`sitemap.xml` 可讀，靜態頁可直接開啟。第一筆**非團隊**的體檢或認領出現時記錄日期。
- [ ] 預期要老實：搜尋收錄與自然流入通常要數週，不承諾短期數字。

## 2. 討論

### Fable (Claude Code) 意見

- 使用者要的是「不靠他引介，外部的人也會自己來用」。這要三件事同時成立：**打得開**（公開網址）、**找得到**（可收錄的頁面）、**用得起來**（共用資料，否則廠商永遠看不到工廠）。目前三件都不成立，只做信任文案不夠。
- 最有機會讓廠商自己上門的是「公開履歷 + 認領更正」：廠商會搜尋自己公司名，看到有人整理了自己的公開資料，就有動機進來更正。這不需要任何人寄信。
- 最大的風險是為了看起來可信而造假，例如假的使用人數或假評價。一被識破就全盤失去信任，所以列為硬性禁止。
- 公開網址需要使用者決定（L4）：用使用者自己的網域掛 Cloudflare（保留現有 `serve-prod`，B 段最簡單），或使用者登入 Cloudflare 一次取得免費固定網址。決定前 A 段照做。
