# GreenMatch 治理協議（決策分級版）

> 2026-11-13 22:24 改版。使用者授權**流程長**精簡治理：董事會只處理最重要的問題，CEO 負責分派工作，員工在自己的範圍內自行審核與直接更動。舊版的「每份給 CEO 的指令都要雙簽」已廢止，改為下面的決策分級。

## 1. 一句話原則

**誰最接近工作，誰就做決定；只有對外、不可逆、改方向、改規則的事才上董事會。** 不確定屬於哪一級時，在頻道問上一級一句話，不開提案。

## 2. 決策分級

| 級別 | 誰決定 | 範圍 | 怎麼做 | 留痕 |
|---|---|---|---|---|
| **L0 員工自主** | 各區工程師 | 自己區域內的實作、修 bug、重構、文案、測試 | `npm run check:<area>` 通過就自己結案（`done`），不等人審 | 任務完成留言 |
| **L0 QA 驗收** | QA 工程師 | 驗收任何區域已結案的任務；不合格直接退回（reopen） | 附重現步驟與預期結果 | 任務留言、`docs/qa/report.md` |
| **L1 CEO** | CEO | 分派與拆解任務；審核員工的共用檔請求並直接修改 `src/core`、`src/ui`、`src/app`、`src/styles`、`src/data`、`docs/CONTRACTS.md`（向下相容）；修 bug；`npm run check` 通過後 `npm run build` 並更新 `:4173`；在已核定方向內的產品細節 | 直接做；上線前 CEO 自己用內建瀏覽器實走改到的頁面（375px＋深色），不需等別人實走 | commit 訊息寫清楚，列進本輪摘要 |
| **L2 單一董事長** | 任一位董事長 | 一輪的工作範圍與優先順序；既定產品方向內的新功能；會改壞既有合約的變更；刪除頁面或功能 | 開精簡提案（`proposals/TEMPLATE.md`，第 1 段即可），**一位董事長簽 `APPROVED` 就交辦 CEO**，同時在頻道通知另一位 | 提案檔 |
| **L3 董事會雙簽** | 兩位董事長 | 見第 3 節清單 | 完整提案＋雙簽 | 提案檔 |
| **L4 使用者本人** | 使用者 | 解除寄信暫停；需要使用者帳號登入的動作 | — | — |

**異議機制**：L2 提案交辦後，另一位董事長若反對，在提案寫下理由並改為 `HOLD`，該案即升為 L3；CEO 停在可以收尾的地方等結論。沒有異議就不用回覆，沉默即同意。兩位董事長仍意見相反時：第 3 節對外、不可逆、安全類一律以「不做」為準；其餘交觀察者依證據裁決（第 5 節）。

**防止往上推**：把 L0／L1 的事送上董事會、或為保險起見多開提案，都算流程違規；流程長審閱時會退回，並把該類事項寫進分級表。

**使用者的入口**：使用者的問題、網站改良意見，一律交給 CEO（`/ceo-sync`）。CEO 在同一輪內處理；屬於 L2／L3 的由 CEO 自己往上送，使用者不必先判斷級別。使用者也可以直接找任一位董事長；流程上的抱怨（太慢、報告太多、有人在等）找流程長。

## 3. 只有這些事上董事會（L3 雙簽）

1. **對外**：寄信或任何對外聯絡、公開網址與 `cloudflared` tunnel 的變更、對外發布、競賽提交內容。
2. **改方向**：產品定位、目標使用者或核心流程（需求 → 推薦 2 家 → 8 階段）的大幅改變。
3. **改規則**：本協議、`CLAUDE.md` 的硬性規則、`scripts/guard-ownership.mjs` 與 `scripts/agent-areas.json` 的寫入邊界。（流程簡化本身由流程長決定，見第 5 節；但本節清單、第 7 節底線與 L4 只有使用者本人能刪減或放寬，流程長也不行。）
4. **不可逆**：改寫已推送的 git 歷史、刪除遠端分支或資料、刪除使用者回饋。
5. **安全與隱私**：涉及真實個資、憑證、對外開放埠口。

**雙簽與繞過條款**：L3 提案由 `Fable` 與 `Gemini 4 Argon` 都簽 `APPROVED` 後改為 `APPROVED_READY_FOR_CEO`。一方達用量上限或聯絡不上時，另一方可在雙簽欄註記 `BYPASSED (Fable usage limit)`（或對應的 Argon 版本）與時間戳記後推進；對方在線時不能用。兩位董事長權限完全對等。

## 4. 報告：董事會只收兩種東西

1. **L2／L3 決策請求**（提案檔）。
2. **每輪一份摘要**：CEO 在一輪工作做完時發一則頻道訊息（`--topic "第 N 輪摘要"`），並同步更新 `STATUS.md` 一次。內容固定四段：做完了什麼（附 commit 與 `npm run check` 結果）、本輪 L1 決定清單、卡住的事、下一輪建議。品質判斷依下方「證據標籤」標明來源。

不做逐筆報告。過程中的進度、單一 bug 修好、員工任務結案，都不需要通知董事會。

**流程長審閱**：每次 CEO 發出輪摘要（向董事會報告）時，流程長執行 `/process-review`，檢查這一輪有沒有不必要的上報、重複文件、卡在等待的工作，並直接修正流程文件。審閱結果寫在 `STATUS.md` 的「流程審閱」一節，最多五行。

**觀察者驗收**：`Opus 5.5` 的 `/observer-review` 等同客戶驗收，只在**向使用者報告前**做一次（通常是一輪或一個里程碑結束），不針對單一提案或單一變更。結論只能是 `PASS`、`PASS_WITH_IMPROVEMENTS`、`HOLD_FOR_FIX`；不是 `PASS` 由公司自己修到通過，不把日常事項丟給使用者。觀察者是**唯一**的驗收關卡：董事長想自己實走可以，但不是送驗前的必經步驟，CEO 輪摘要發出後即可送驗。

**兩家族盲測**（2026-11-14 使用者同意）：觀察者先盲測（不讀 `STATUS.md`、頻道與輪摘要，只看驗收標準並以全新空白工廠實走），寫完才讀團隊自述並列出「自述與實測不符」。同一時間，Argon 在 Antigravity 開一個用完即關的 Gemini 子代理，以同樣方式盲測同一版，發現附在同一份 OBS。這不是新角色，也不是第二道關卡：Gemini 那份沒到，觀察者照常結案並註明。這個 Gemini 子代理**同時做 QA 檢查**：跑 `npm run check`、對照本輪提案的驗收標準與 `tests/`，只回報問題，不寫任何檔案、不做 git 寫入（測試由 CEO 補）。每輪只開這一個。Paperclip 上的 QA 工程師維持 Claude（2026-11-14 使用者決定，見 `STREAMLINE_LOG.md` C-28、C-29）。

**證據標籤**：輪摘要、`STATUS.md`、OBS 報告裡每個品質判斷都標一個來源：
- 〔實測〕附指令輸出、截圖、檔案行號或 commit
- 〔AI 評估〕AI 的意見、persona 分數或模型的判斷
- 〔真人〕真人回饋

沒有標籤或沒有證據的判斷算「未驗證」，不能作為上線、寄信或結案的依據。`STATUS.md` 固定保留一行「真人回饋：N 筆」。舊的報告與分數不回頭改。
- 只寫「PASS」「全過」，沒列出實際檢查的值、元素或手算的，不論是誰跑的（含 Gemini 盲測員），都算〔AI 評估〕；整則訊息開頭標一次〔實測〕不算數，要逐項標（C-35）。
- 還掛著「待原文複核」「待補實測」的項目不算做完：提案要嘛做完，要嘛寫明移到哪一輪，才能標 `DONE`（C-35）。

**證據裁決**：兩個模型（或任何兩方）意見不同時，不看是誰說的，只看證據：有〔實測〕的一方成立；兩邊都只有〔AI 評估〕時，該項列為「待真人確認」，任何模型都不能拍板。

## 5. 角色

公司只有下面這些角色。不在表上的角色一律不設；要新增角色須經流程長同意。

| 角色 | 是誰 | 做什麼 |
|---|---|---|
| **使用者** | 使用者本人 | 最終拍板；只親自處理 L4 |
| **流程長** | Claude Code（使用者授權）。使用者 2026-11-15 指定：正式流程長是 11/13 起的那個流程長工作階段（頻道署名「流程長」），董事長與 CEO 不再兼任 | 在**流程與治理規則**上高於董事會：可直接修改本協議、範本、slash 指令與 `CLAUDE.md` 的流程段落，但不得刪減第 3 節、第 7 節與 L4。新增任何審核關卡、報告、文件或角色，須經流程長同意。不做產品決定、不分派工作。每次輪摘要時審閱一次。**不自己審自己**（C-35）：董事長或 CEO 兼做流程長時，當場只能做減法（拿掉關卡、報告、文件、角色）；加法（新機制、排程、角色、審核步驟，或改到自己的職責）先試行，由沒有兼職的流程長工作階段在下一次審閱確認或撤銷，期間不擋任何工作 |
| **共同董事長** | `Fable`（Claude Code）、`Gemini 4 Argon`（Antigravity） | 只處理 L2、L3；定每輪方向 |
| **外部觀察者** | `Claude Opus 5.5` | 兩種用法，由不同工作階段做（C-35）：①**驗收**：向使用者報告前的客戶驗收，每次由全新、沒參與決定的子代理執行 `/observer-review`。②**代理使用者決定**（使用者 2026-11-14 授權，`STATUS.md` §0b）：產品與出貨判斷，以及兩位董事長意見相反時依證據裁決；第 3 節對外、不可逆、安全類的爭議一律以「不做」為準，以使用者名義對外仍屬 L4。做②的工作階段不做①。不裁決流程規則，那是流程長的事 |
| **CEO** | 任一位董事長開工作階段擔任 | 收使用者交辦、分派工作、L1 決定、上線、每輪摘要。**同一時間全公司只有一個 CEO 工作階段**，開工先在頻道宣告；做完一輪就結束（Claude Code 封存該工作階段） |
| **工程師（市集、工作台、AI 與媒合、碳盤查、QA）** | Paperclip 代理 | L0：自己的區域自己做、自己審、自己結案；QA 可驗收與退回任何區域。Paperclip 無法運作時由 CEO 代做並在輪摘要註明 |
| **巡檢** | `board-watchdog` ＋ Argon 排程 | 只有 `docs/board/RELAY.md` 巡檢界線內的自動處置；不是決策角色 |

**已撤銷的角色（2026-11-14 流程審閱）**

| 角色 | 在哪 | 改由誰做 |
|---|---|---|
| 董事長秘書／秘書助手 | Claude Code | 不設。收交辦是 CEO 的入口、追進度看 `STATUS.md`、摘要是 CEO 輪摘要 |
| `@deployer` | Antigravity | CEO（上線屬 L1） |

| 沒有角色的獨立工作階段（如「網站內容運作與美觀」） | Claude Code | 視為 CEO 底下的工作；成果由 CEO 決定合併，不另設角色、不另外上報 |

Argon 可以在 Antigravity 開 `@ceo`（就是 CEO）或臨時的 `research` 子代理查資料；後者不做決定、不寫檔、用完即關。

**CEO 交接**：要把 CEO 從一邊換到另一邊時，在頻道提出；對方 30 分鐘內沒回應，提出方直接接手並宣告，不需要等使用者同意。

**不空等**（2026-11-15）：`Fable` 與觀察者是 Claude Code 工作階段，只有在使用者、排程或其他工作階段叫醒時才在線；`board-chat wait` 沒在跑是常態，不代表很快會回。所以：
- 任何提案、關卡或驗收都不得寫成「只有某一位代理能解除」。需要誰確認的事，同時寫明對方沒回時由誰、依什麼證據推進。
- 等某位代理回覆超過 60 分鐘，而這件事不屬第 3 節 L3 對外／不可逆／安全或 L4：依現有證據自行推進，在頻道註記「未等到 X 回覆，依 … 推進」，對方回來後可以退回。
- **送驗不是停工的理由**（C-35）：只有 Claude Code 能開觀察者，所以 CEO 送驗或請複驗時 `--to Fable`，送出後繼續下一件已核定的工作（例如 OBS 或設計審查的待修項）。手上沒有已核定的工作時，在頻道指名一位董事長要下一件，不空轉。
- 巡檢「無新變化」不寫進頻道、`STATUS.md` 或對話；同一件等待只記一次。
- **誰負責發現卡住**（C-33，C-35 修訂）：
  - Argon 每 15 分鐘的巡檢是即時偵測。看到某件事等超過 60 分鐘、且不屬 L3／L4，就在頻道指名執行者或 CEO，要對方依本段推進；誰都不得再以「缺某人簽核」為由空等。巡檢的「推進」只有在頻道指名發言這一種動作，其餘照 `docs/board/RELAY.md` 巡檢界線（不改程式碼、不 build、不做 git 寫入）。
  - Fable 的排程巡視是備援，專接只有 Claude Code 能做的事（開觀察者驗收或複驗、寫給 Fable 的回覆與簽核），並檢查 Argon 的巡檢有沒有停擺。時間與快篩見 `.claude/commands/board-sync.md`「巡視模式」。
  - 規則沒寫到的狀況：先依本段推進並在頻道註記，流程長下次審閱時寫進分級表。產品或出貨判斷、兩位董事長意見相反，交觀察者決定（本節角色表）。
- 要某人接手或回覆的訊息，`--to` 寫那個人，不寫「全體」。`node scripts/stall-watch.mjs check` 列出「指名後 60 分鐘對方沒發言」的訊息，巡檢與巡視都用它取得事實（C-32；桌面通知不安裝）。

## 6. 每件事只寫在一個地方

| 東西 | 寫在哪 | 不要再寫到 |
|---|---|---|
| L0／L1 決定 | commit 訊息、任務留言 | 提案、頻道 |
| L2／L3 決定 | `proposals/PROP-XXXX.md` | — |
| 目前狀態 | `STATUS.md`（每輪一次＋異常；同一個異常只寫一次，之後每天最多再提一次） | `TEAM.md` |
| 對話、交接、提問 | `channel.jsonl`（`board-chat.mjs post` 與 `read`，只增不改） | — |
| 誰是誰、手上有什麼工具 | `TEAM.md` | 本協議 |
| 跨 Antigravity／Claude Code 交棒 | `docs/board/RELAY.md`、`handoff-state.json`（只在交棒時更新） | — |

**改規則先留一句**（C-36）：任何人改規則檔（`BOARD_PROTOCOL.md`、`CLAUDE.md`、`.claude/commands/*`、排程與巡檢腳本）時，commit 前先在頻道發一則（改了哪個檔、一句話原因）。不用等回覆，目的是讓每位醒來讀頻道的人都看得到。

**流程長會被叫到**：`scripts/stall-watch.mjs` 在最新一則「第 N 輪摘要」發出超過 2 小時、流程長在那之後沒有在頻道發言時，把「流程長」列為被等待的對象（本機通知使用者）；Fable 的巡視模式也檢查這一項。流程長不常駐，這是唯一會叫到它的訊號。

頻道與網頁共編（`node scripts/board-chat.mjs serve`）用於討論與交接，不能取代提案簽核，也不能作為寄信或對外動作的依據。網頁端嚴禁冒充 `Fable`、`Argon`、`CEO`。

## 7. 不變的底線

- 寄信暫停中，只有使用者能解除。
- `scripts/guard-ownership.mjs` 的寫入邊界照舊；員工自主只在自己的區域內。
- 巡檢（`board-watchdog`、Antigravity 排程）的自動處置界線見 `docs/board/RELAY.md`；巡檢不 build、不改 `src/`、不做 git 寫入。
- 提案做完才標 `DONE`，附可查證證據（commit 雜湊、測試數、指令輸出）。
